# Encrypted Codex Local Work-History Digest

## Why This Exists

The current ChatGPT access is a company-provided API/workspace. A company API account is not equivalent to a normal ChatGPT web account, so a web-account data export cannot be assumed to cover the Codex work recorded locally. No official `conversations.json`, `chat.html`, or OpenAI export archive was found on this machine.

This package therefore builds a migration-oriented digest from the local Codex database and encrypts it with AES-256-GCM using the same separately stored key as the credential vault.

Encrypted archive: `archive/codex-work-history/codex-work-history-20261102.aesgcm`

## Included

- Titles, time ranges, and turn status for 300 local Codex threads with retained messages.
- 3,453 original user requests and 6,962 assistant final or unspecified-phase responses as `threads.jsonl`, grouped by thread and ordered in time.
- `thread-catalog.csv` for fast discovery.
- `session-index.jsonl` for the local thread index.
- Memory summary, searchable memories, raw-memory index, and rollout summaries from `.codex/memories/`.
- `archive-metadata.json` with export time, counts, exclusions, and SHA-256 hashes.

## Deliberately Excluded

- Reasoning, commentary progress updates, command traces, tool arguments/results, image binaries, file diffs, and caches.
- The full `thread_history_1.sqlite`, `logs_2.sqlite`, and approximately 933 MB of raw session/archived-session files, because uploading hundreds of megabytes of tool logs provides poor retrieval value.
- Internal prompts generated by the automatic memory observer.

The exclusions reduce size and noise while retaining requests, conclusions, and local memories. Project SQL, result files, and skills remain available at their separate GitHub paths.

## Decrypt and Use

The key file `huya_ty-env-files.key` remains outside the repository and must be transferred through an encrypted medium or password manager.

```powershell
node vault/decrypt-env-files.mjs archive/codex-work-history/codex-work-history-20261102.aesgcm <key-file> <new-staging-directory>
```

Start with `archive-metadata.json` and `thread-catalog.csv`, then search `threads.jsonl` by thread. The `memory/` directory restores working habits, historical definitions, and troubleshooting lessons.
