# PSM+DID 因果推断分析

## 分析理念

这套方法解决一个简单的业务问题：**"这个活动/策略/干预到底有没有用？有多少用？"**

直接比较实验组和对照组的均值差异会遇到两个陷阱：
1. **选择偏差**：参与活动的用户可能本身就比不参与的用户更活跃（混淆变量），把这种"先天差异"归因为活动效果会高估影响
2. **时间趋势**：即使没有活动，用户行为也会随节假日、版本更新等自然波动，把时间趋势当成活动效果同样会错估

PSM+DID 组合策略分两步解决：
- **PSM（倾向得分匹配）**：为每个实验组用户找一个"各方面都像但没参与活动"的对照组用户，消除选择偏差
- **DID（双重差分）**：对比两组在活动前后的变化差异，剔除时间趋势

最终得到的 **DID 净效应** = 活动真正的因果影响。

## 使用方式

### Step 0：样本量可行性预审（强制门槛）

任何正式 PSM、DID、PSM-DID、全量扫描、长任务或报告生成之前，先做轻量级样本量审计并向用户汇报。这样可以避免在有效样本不足、匹配覆盖率过低、控制组重复过度或指标波动过大时直接产出看似精确的结论。预审只读取已有元数据、缓存索引、checkpoint、样本统计或必要的轻量抽样；如果用户明确要求复用缓存，不得为了预审重建完整缓存或重新扫描原始 CSV。

预审至少检查并记录：

1. **样本定义与候选量**：实验组/候选对照组定义、分析粒度、cohort/事件日期范围、去重规则、排除规则；分别统计匹配前实验组人数、候选对照人数、唯一用户数和可用日期/分层数。
2. **匹配后可获得样本**：根据历史 checkpoint、已有匹配率或轻量试算估计匹配对数；同时报告预期实验组覆盖率、唯一对照用户数、控制组重复使用次数和必要的有效样本量，而不能只报告“匹配对数”。
3. **统计设计参数**：优先向用户确认主指标、最小可检测增量（MDE）、显著性水平 α 和统计功效 Power。用户未指定时，只能明确标注默认假设（通常 α=0.05、Power=80%），并输出多档 MDE 敏感性结果，不得把某个默认 MDE 当作业务承诺。
4. **样本量估算**：
   - 1:1 匹配且以 DID 差值为分析单位时，令 `D_i=(Y_after-Y_before)_treatment-(Y_after-Y_before)_control`，使用 `n_pairs=[(Z_(1-α/2)+Z_power)×SD(D_i)/MDE]^2` 估算所需匹配对数。
   - 未匹配的两独立组均值比较可用 `n_group=2×[(Z_(1-α/2)+Z_power)×σ/MDE]^2`；二分类 outcome 使用两比例样本量公式。
   - 指标严重偏态或控制组重复匹配时，不能只依赖普通 t 检验公式；应使用按用户/控制用户聚类的稳健标准误、cluster bootstrap 或基于历史方差的模拟功效分析。
5. **结论分级**：
   - `样本充足`：预期匹配量达到目标，关键指标的目标 MDE 在设定 α/Power 下可识别，且 SMD/共同支持域/重复使用风险可接受。
   - `样本边界`：只能识别较大的效果，或匹配覆盖率、唯一控制用户数、指标波动、日期/分层小样本存在风险。
   - `样本不足`：预期匹配量明显低于所需量，或无法支持主指标的目标 MDE。此时不得直接开始正式 PSM-DID；应先向用户报告并建议扩大时间范围、放宽但记录匹配条件、合并合理分层、改用描述性/探索性分析，或由用户明确授权继续。

预审汇报必须先发给用户，至少包含以下字段：

```text
样本量预审结论：充足 / 边界 / 不足
主指标与目标MDE：...
α / Power：...
匹配前：实验组N、候选对照N、唯一用户N
预计匹配后：匹配对数、实验组覆盖率、唯一对照用户数
控制组复用：是否允许、最大复用次数、有效样本量/聚类处理
预计最大SMD或历史SMD：...
建议：正式执行 / 先调整设计 / 仅做探索性分析
```

默认在预审汇报后暂停正式执行，等待用户确认；如果用户已在任务中明确授权“按默认参数直接执行”或“只做样本预审”，可以按其授权继续。预审结论、假设、公式和实际匹配后的样本量必须写入最终日志及报告，避免把事后样本量当成事前功效保证。

### 控制组复用 / overlap matching 分支

控制组复用是可选的匹配设计，不等同于普通不重复 1:1 匹配，也不等同于 overlap weighting。它通常规定“每个实验用户最多出现一次，但同一个控制用户可以被多个实验用户匹配”。复用可以提高实验组覆盖率，尤其适合控制候选不足或日期/分层内重叠有限的场景；代价是控制用户之间不再独立，名义匹配对数会高估有效信息量。

#### 触发条件与选择优先级

按以下优先级决定是否启用该分支：

1. **用户明确要求时触发**：用户提到“控制组允许重复匹配”“控制复用”“同一个对照可匹配多个实验用户”“overlap weighting”等要求时，启用对应方案，并在预审汇报中先说明依赖结构和统计处理。
2. **已有结果明确采用复用法时触发**：用户要求复用既有 checkpoint、结果目录或历史版本，且其匹配元数据标明 `control_reuse` 或 overlap weighting 时，沿用原方案，不把它改写成不重复 1:1；同时核对其唯一对照用户数、复用频次和稳健推断方式。
3. **不重复匹配不足时只建议、不自动切换**：如果 `no_reuse_1to1` 的覆盖率低于用户目标、日期/分层内控制候选不足或目标 MDE 无法达到，可以把控制复用作为备选方案；必须先向用户汇报“不复用结果 + 复用预期收益 + 依赖风险”，得到用户确认后才能切换。
4. **用户未指定时的默认规则**：默认先做不重复 1:1 匹配或使用用户已指定的方案，不得因为复用后匹配对数更多、覆盖率更高就自行采用控制复用。
5. **禁止触发的情况**：如果用户明确要求“控制组不可重复”“一个用户只能出现一次”，不得启用控制复用；如果只有跨日期复用而没有业务或设计依据，不得把跨日期重复当作合法 overlap。

执行前必须确认并记录以下设计选择：

1. `no_reuse_1to1`：控制用户最多匹配一次；匹配对数基本可视为两组独立用户对，但仍需考虑同 cohort/date 聚类。
2. `control_reuse`：实验用户最多一次，控制用户允许多次；必须保持同一 `dt/index_dt` 或用户明确指定的 cohort 内匹配，不允许跨日期随意复用。
3. `overlap_weighting`：按倾向得分重叠程度加权；它是加权估计，不应在报告中写成“匹配对数”，必须报告权重和有效样本量。

控制复用版本必须同时输出：

- 实验组独立用户数；
- 名义匹配对数；
- 唯一对照用户数；
- 控制用户复用频次分布、平均/中位复用次数和最大复用次数；
- 控制侧复用权重的 Kish 有效样本量：`ESS_control=(Σw)^2/Σ(w^2)`，其中 `w` 为每个唯一控制用户的被复用次数。该 ESS 是诊断性下限提示，不替代聚类功效分析；
- 按控制用户 `user_ukey` 聚类的稳健标准误或 cluster bootstrap 结果，必要时同时按 cohort/date 做双向或分层稳健处理。

控制复用下的样本量判断规则：

- 不得把重复出现的控制用户当作新的独立用户，也不得只用名义匹配对数判断“样本充足”；
- 初步公式可以先用匹配对层面的 `SD(D_i)` 估算，再用复用导致的聚类设计效应、控制侧 ESS 或模拟功效进行保守校正；
- 如果最大复用次数很高、控制侧 ESS 明显低于名义对数，样本量预审最多判为“样本边界”，除非聚类 bootstrap 或模拟功效明确通过；
- 控制复用结果必须与 `no_reuse_1to1` 结果并列作为敏感性分析。若两者方向和量级不一致，应优先解释复用结构、日期/分层构成和重尾指标，而不是选择数值更大的版本作为主结论。

报告中统一使用以下样本表述，避免误导：

```text
匹配对数 = 名义配对记录数，不等于独立用户数
实验组独立用户 = ...
唯一对照用户 = ...
控制组复用 = 是/否；最大复用次数 = ...
控制侧 Kish ESS = ...（仅作诊断）
统计推断 = 按控制用户聚类稳健标准误 / cluster bootstrap
```

### 触发后先做的事

1. **确认数据文件位置和格式**（CSV推荐，编码 utf-8-sig）
2. **先确认分析口径 / 样本粒度**：
   - 不要默认把数据粒度当成用户日、去重用户或首次触达；在建模前先问用户需要哪一种口径。
   - 默认给出以下两个主选项，并用业务语言解释差异：
     1. **用户日事件口径 PSM/ATT**：一行是一条“用户 × 日期/事件”记录，同一个用户可在多个日期出现多次。估计的是“某个日期当天参与/触达/观看”在事件层面的关联增量或 ATT，适合回答“当天触达这件事对后续行为有什么影响”。
     2. **去重用户首次触达/首次观看 + 用户级 PSM ATT**：每个用户只保留一行。实验组取该用户第一次触达/第一次观看日期；对照组通常取“从未触达/从未观看用户”的首次活跃且未触达日期。估计的是用户级首次触达口径下的 ATT，适合业务理解“这批第一次看过/触达过的用户后续留存和活跃表现如何”。
   - 如果用户没有明确选择，先暂停确认；如果用户已在 prompt 中明确写了“用户-日期”“同一用户可多次出现”“首次观看”“去重用户”等关键词，则按其描述执行，并在报告中复述口径。
3. **提前询问业务预期和关键混杂变量**：
   - 先问用户：业务上预期 treatment 是否应该有强增量？如果用户预期“理论上不应有明显差异”，后续要把普通 PSM 结果当作可疑信号来反查混杂因素，而不是直接下因果结论。
   - 先问用户最关心的 outcome 是什么（例如留存、活跃、观看深度、消费），以及哪些前置变量最可能同时影响 treatment 和 outcome（例如前 N 天活跃天数、观看天数、观看时长、消费金额）。
   - 如果用户明确重视某个前置变量（如 `before*_active_dcnt`），不要只把它放进 propensity score 模型；要询问是否启用“关键混杂变量强约束 / 分桶内 PSM”的严格口径。
   - 默认提示用户可选：
     1. **普通 PSM**：所有前置变量作为协变量进入 PS 模型。
     2. **严格分层 PSM**：先按关键混杂变量 exact/coarsened exact 分层，再在层内做 PSM，适合验证 ATT 是否由关键混杂因素残留驱动。
4. **识别列名**：
   - 哪个列是处理变量（0/1，1=实验组/参与活动）？
   - 哪些列是 `before_*`（匹配特征 + 前值参照）？
   - 哪些列是 `after_*`（DID 结果变量）？
   - 有没有 `is_interest_*` 列（可选子人群）？
   - 有没有消费金额列（用于 LTV 补充分析）？
5. **确认是否需要子人群分析**（默认跳过，有需要再开）

### 口径选择与建模分支（优先级高）

PSM/ATT 的样本粒度会改变指标含义。执行前必须把口径写入代码注释、日志、Word/Excel 报告和结论边界中。

#### A. 用户日事件口径 PSM/ATT

适用场景：数据每行是“用户 × 日期/事件”，同一个用户可以在不同 `dt` 出现多次；用户想评估“当天 treatment”对 D6 留存或后续 D1~D6 行为的影响。

执行规则：
- 保留用户日粒度，不按 `user_id` 去重。
- treatment/control 必须在同一 `dt` 内匹配；如果用户要求或日期样本充足，优先逐日估计 propensity score 并逐日匹配。
- 对重复用户导致的非独立性，统计推断优先使用按 `user_id` 聚类的稳健标准误，或按 `user_id` 的 cluster bootstrap。
- 结论必须表述为“用户-日期事件层面当天参与/观看/触达的关联增量/ATT”，不要写成去重用户首次触达效果。

报告中必须明确：
- treatment D6 留存率 = 匹配成功的 treatment 用户日样本中，`is_6d_retain=1` 的比例。
- control D6 留存率 = 与这些 treatment 用户日匹配上的 control 用户日样本中，`is_6d_retain=1` 的比例。
- 全周期汇总按匹配成功的用户日样本量加权，不简单平均每日结果。

#### B. 去重用户首次触达/首次观看 + 用户级 PSM ATT

适用场景：用户更关心“这批看过/触达过活动内容的用户”本身的留存，或明确要求“去重用户”“首次观看”“首次触达”“业务更好理解的留存口径”。

执行规则：
- treatment 组：对每个曾经 treatment=1 的用户，只保留其第一次 treatment 日期作为该用户的 `index_dt`。
- control 组：优先使用“全周期从未 treatment=1 的用户”，只保留其第一次活跃且 treatment=0 的日期作为 `index_dt`。如果数据不支持识别全周期从未 treatment，应在报告中说明替代口径。
- 每个用户最终只保留一行，构造用户级分析样本；`dt/index_dt` 是首次触达或首次活跃日期。
- PSM 协变量只能使用 `index_dt` 之前的特征；treatment 后的 outcome 不能进入 propensity score。
- 匹配仍需 exact match on `index_dt`/`dt`，避免不同日期 cohort 混配。
- 主结果输出用户级 PSM ATT，包括 D6 留存和关键后续行为；对于世界杯观看这类场景，至少输出 `is_6d_retain` 和 `after6d_active_dcnt`。

报告中必须明确：
- 首次观看用户 D6 留存率 = 去重后的首次观看用户中，首次观看日后第 6 天仍活跃的用户占比。
- 匹配后 treatment D6 留存率 = 成功匹配的首次观看用户中，D6 活跃的比例。
- 匹配后 control D6 留存率 = 与其匹配的从未观看/未触达用户中，首次活跃日后第 6 天活跃的比例。
- ATT = 匹配后 treatment 均值 - 匹配后 control 均值；这是可观测特征匹配后的关联增量，不直接表述为绝对因果。
- 若同时输出未匹配的“原始首次观看留存率”，必须与 PSM ATT 分开展示，避免用户把总体留存和匹配后 ATT 混为一个指标。

#### C. 业务预期反推混杂因素 + 严格分层 PSM（当用户质疑普通 PSM 结果时优先启用）

适用场景：
- 用户有明确业务预期，例如“理论上 treatment 不应该带来强增量”“两组行为类似时应该没有明显差异”。
- 普通 PSM 后 ATT 仍明显偏大，用户怀疑实验组和对照组仍没有真正可比。
- 用户特别重视某个前置变量的可比性，例如前 N 天活跃天数、前 N 天观看天数、历史消费水平。

核心思路：
- 普通 PSM 把关键变量作为模型协变量，但不会保证该变量在每一层都完全一致。
- 如果某个前置变量同时强影响 treatment 和 outcome，就把它从“模型协变量”升级为“匹配约束”。
- 先按关键混杂变量 exact/coarsened exact 分层，再在层内做 PSM；最后同时看整体 ATT 和各层 ATT。

标准执行流程：
1. **先复述业务预期**
   - 报告中写清楚用户的先验判断，例如：“如果活动/内容本身没有强增量，那么在可观测行为相似后，treatment/control 的留存和活跃应接近。”
   - 如果普通 PSM 结果与该预期冲突，不要直接写“活动显著有效”；先进入混杂诊断。

2. **识别最可能残留的混杂变量**
   - 对留存、活跃类 outcome，优先检查前置活跃强度：`before*_active_dcnt`、`before*_active_rate`。
   - 对观看深度类 outcome，优先检查前置观看强度：`before*_watch_duration`、`before*_watch_dcnt`、`before*_watch_anchorcnt`、`before*_watch_gamecnt`。
   - 对消费类 outcome，优先检查前置消费金额、是否消费、付费频次。

3. **做严格分层匹配**
   - 固定 exact match on 日期 / cohort（如 `dt` 或 `index_dt`）。
   - 对关键混杂变量做 exact 或 coarsened exact matching。
   - 示例：前 29/30 天活跃天数可分桶：
     ```
     0
     1-3
     4-7
     8-14
     15-21
     22-29/30
     ```
   - 在每个 `日期 × 关键变量桶` 内再估计 propensity score 并做 1:1 nearest-neighbor matching。
   - caliper 可比普通 PSM 更严格，例如 `0.05 × logit(propensity score) 的标准差`；如果匹配率过低，再放宽到 0.1 或 0.2。

4. **输出整体 ATT，但不要简单平均分桶 ATT**
   - 主结果：合并所有匹配成功样本后直接计算整体 treatment/control 均值差，等价于按匹配样本量加权。
   - 不要把各日期/各桶 ATT 简单算术平均。
   - 同时输出每个分桶的 ATT、样本量、95% CI、p-value，用来判断方向是否稳定。

5. **平衡性报告要区分整体和局部分桶**
   - 输出匹配后整体 SMD，特别是关键混杂变量的整体 SMD。
   - 同时输出分桶内局部最大 SMD；如果局部小样本层 SMD 较高，要解释这是局部层现象，不要用它替代整体匹配质量。
   - 对关键混杂变量，目标是整体 SMD 接近 0；例如 `before*_active_dcnt` 被强约束后应显著收敛。

6. **用“结果是否收敛”判断混杂影响**
   - 对比普通 PSM 与严格分层 PSM：
     ```
     收敛比例 = (普通PSM_ATT - 严格PSM_ATT) / 普通PSM_ATT
     ```
   - 如果严格控制后 ATT 大幅收敛，说明原结论很大一部分来自关键混杂变量残留。
   - 如果某些 outcome 仍有残余差异，继续检查更贴近该 outcome 的前置变量；例如观看时长残余差异可能来自历史观看时长/观看天数，而不只是活跃天数。

7. **报告解释模板**
   - 当严格匹配后留存/活跃 ATT 明显收敛：
     > “当把前置活跃水平作为强匹配约束后，留存和活跃差异明显收敛，说明普通 PSM 中的部分增量来自原本活跃水平差异；当前结果更适合解释为可观测特征匹配后的残余关联，不宜直接表述为强因果增量。”
   - 当分桶 ATT 方向不稳定：
     > “整体 ATT 并非所有层级稳定正向，而是不同活跃层级方向和强度不同；因此应谨慎使用整体平均结论。”
   - 当观看/消费等指标仍有残余差异：
     > “残余差异可能来自更细的内容消费偏好或付费偏好，建议进一步对历史观看深度/付费行为做强约束或分层稳健性检验。”

## 工作流程

### 大文件 / 多日期长任务执行策略（优先级高）

当输入文件很大（例如 CSV 超过 1GB）、按日期/分层逐批建模，或用户机器内存/稳定性可能成为瓶颈时，优先使用**单进程逐日 checkpoint + resume**，而不是盲目并行 worker 或一次性把所有日期结果堆在内存里。

核心执行规则：

1. **逐日/逐分层独立落盘**
   - 每个日期或分层单独完成：数据读取 → 特征处理 → PSM 匹配 → 平衡性检验 → outcome 汇总。
   - 每完成一个日期，立刻写入独立 checkpoint 目录，例如：
     ```
     _psm_work/checkpoints/{dt}/
       matched.pkl
       balance.csv
       outcomes.csv
       preprocess.csv
       daily_stats.json
       DONE.txt
     ```
   - `DONE.txt` 是该日期已完成的标记。后续汇总只读取这些 checkpoint，不依赖内存中的临时对象。

2. **resume 模式默认跳过已完成日期**
   - 启动时先扫描 checkpoint：
     ```
     completed = 已存在 DONE.txt 的日期
     todo = 全部日期 - completed
     ```
   - 如果中途电脑重启、进程终止或用户打断，下次从下一个未完成日期继续，不重跑已经完成的日期。
   - 运行日志要明确告诉用户：
     ```
     resume mode completed={N_done} todo={N_todo}
     当前日期完成后已写入 _psm_work/checkpoints/{dt}
     ```

3. **每天结束后释放内存**
   - 每个日期完成并落盘后，删除当天的大对象（原始 DataFrame、特征矩阵、匹配样本等），并执行：
     ```python
     del res
     gc.collect()
     ```
   - 不要把所有日期的 `matched_df`、`balance_df`、`outcome_df` 一直追加在内存里；最终报告阶段再从 checkpoint 分批读取并合并。

4. **运行中监控 checkpoint 和内存**
   - 长任务运行时，定期检查：
     - checkpoint 是否已落盘；
     - Python 进程内存是否回落到合理范围；
     - 每日匹配率、最大 `|SMD|` 是否异常。
   - 如果发现内存不释放或持续升高，优先排查是否仍保留跨日期大对象；必要时压缩 dtype、减少列、减少复制，或只保留汇总结果而非完整匹配样本。

5. **谨慎使用并行 worker**
   - 只有在确认机器内存足够、每个 worker 写入互不冲突的独立目录、且单 worker 峰值内存明确可控时，才考虑并行。
   - 并行 worker 不能同时写最终 Word/Excel；只能写各自分片结果，最后由主进程统一合并。
   - 如果出现黑屏、死机、系统更新后中断、内存持续高占用等迹象，立即切回单进程 resume 模式。

6. **CSV 分块扫描与有界候选抽样**
   - 对大 CSV，使用 `pd.read_csv(..., chunksize=...)` 分块读取；初始分块建议为 100,000 至 200,000 行，并根据进程 RSS 内存与吞吐动态调整。不要因内存低于已约定的预警阈值而无故中断。
   - 需要逐行处理时，优先使用 `df.itertuples(index=False, name=None)`，不要对整块数据先调用 `df.to_dict("records")`。前者逐行产出 tuple；后者会为块内每一行预先创建 dict，即使多数行最终不会进入候选样本，也会产生不必要的 CPU 与内存开销。
   - 对照候选按“日期 × 强制分层变量”分别处理，优先用固定哈希抽样或 reservoir sampling；每层必须设置上限（例如 3,000 人）。不得维护覆盖全扫描范围的 `seen` UKEY 集合；最多只保留当前候选池对应的 UKEY 状态。
   - 日期或分层处理完成后，将候选、匹配样本和必要的汇总指标写入独立 checkpoint，再释放 DataFrame、候选池及去重状态。后续汇总阶段按 checkpoint 读取，避免在内存中累积全量候选或完整原始样本。
   - 性能优化不得改变实验/对照定义、事件日期、强制分层变量、固定随机种子、候选上限或匹配规则。优化前后应记录候选样本量、匹配率与 SMD，用于验证结果可复现且统计口径未漂移。

完成 Step 0 的样本量可行性预审并得到用户确认后，按以下 6 个正式分析步骤执行。每一步都说明了"为什么不能跳过"。

### Step 1: 数据加载与清洗

**为什么重要**：NaN 和 Inf 会导致 sklearn 的 StandardScaler 和 LogisticRegression 直接崩溃。不能在匹配之后才处理——PSM 需要完整无缺的特征矩阵。

```python
# 清洗逻辑（模板脚本中的 safe_fillna 已封装好）
# 对每个数值列：coerce → median fill → inf replace → zeros finale
```

清洗后报告：总行数、实验组/对照组人数、缺失列处理情况。

### Step 2: PSM 倾向得分匹配

**为什么重要**：这是消除选择偏差的核心步骤。如果跳过 PSM 直接做 DID，实验组和对照组的初始差异（如实验组本来就比对照组活跃 20%）会被错误地归因为活动效果。

关键参数（可调整，但以下默认值已经过多次验证）：
- 倾向得分模型：LogisticRegression(max_iter=1000, random_state=42)
- 匹配算法：KDTree 1:1 最近邻
- 卡钳阈值：0.05（倾向得分差超过此值的不匹配，保证匹配质量）
- 对照组降采样：超 150 万时自动降采（加速匹配，对结果影响可忽略）

匹配前必须明确控制组是否允许复用。默认使用 `no_reuse_1to1`；如果用户选择 `control_reuse` 或已有 checkpoint 明确采用控制复用，则保留复用频次和唯一对照用户标识，不得把复用后的重复记录去重后再假装是普通 1:1 匹配。控制复用版本的 p 值和置信区间必须使用按控制用户聚类的稳健方法，并在样本量预审及最终报告中同时列出名义匹配对数与有效/唯一样本量。

匹配后报告：匹配成功数/率、卡钳内匹配比例。

### Step 3: 平衡性检验（SMD）

**为什么重要**：PSM 是否真正消除了两组差异，必须有量化证据。不能"假设匹配做好了"——需要用 SMD 检验来验证。

**为什么用 SMD 而非 p 值**：在大样本中，即使差异极小（如两组均值差 0.001），p 值也可能"显著"。SMD 是效应量指标，衡量差异的实际大小，不受样本量影响。

通过标准：所有匹配特征的 |SMD| 在匹配后 < 0.1。若有不通过的，提示具体特征名和 SMD 值，建议调整卡钳阈值或匹配特征。

同时输出 Love Plot（匹配前后 SMD 对比图），直观展示平衡性改善。

### Step 4: DID 双重差分估计

**为什么重要**：这是直接回答"活动有无因果效应"的步骤。DID 同时减去了实验组自身的前后变化和对照组的前后变化，只留下净因果效应。

**标准 DID 公式**：
```
T0 = 实验组before均值    T1 = 实验组after均值
t0 = 对照组before均值    t1 = 对照组after均值
DID = (T1 - T0) - (t1 - t0)
净效应% = DID / T0 × 100%
```

**为什么需要双检验**：
- 均值 t 检验对正态分布假设敏感，极端值会拉偏结果
- 中位数 Mann-Whitney U 检验是非参数方法，对偏态分布（如付费金额）更稳健
- 两个检验方向一致 → 结论更可信；方向矛盾 → 可能存在稀释效应（见 LTV 补充分析）

每个指标输出 18 个字段（见 `scripts/psm_did_template.py` 的 `did_records` 结构），覆盖均值和中位数两个视角。

### Step 5: LTV 补充分析

**什么时候触发**：当 `after_consume_amount`（或用户指定的消费金额列）的 CV(变异系数) > 500% 且均值/中位数 DID 都不显著时。

**为什么需要这一步**：付费金额的分布极度偏态（大部分用户 = 0，少数用户 = 大额），CV 可能高达 1000-3000%。在这种数据上做 t 检验基本是浪费时间——无论真实效应多大，p 值都很难显著。

完整的方法论和判定矩阵见 **`references/ltv-methodology.md`**，要点如下：

1. **pay_rate（付费转化率）**：二分类指标（是否付费），CV ≈ 0%，最可靠的 LTV 信号
2. **ARPPU（每付费用户平均收入）**：仅对付费用户子集计算，排除零值后 CV 降至 50-200%
3. **稀释效应诊断**：当 ARPPU 均值和中位数方向矛盾时，自动检测付费用户数比并给出诚实解读

报告的叙事逻辑是：**先给结论 → 再展示方案 → 然后分层展开证据 → 最后回到总结**。读者应该能在不翻数据表的情况下，仅通过读标题和 bullet 就能把握核心信息。

##### 报告标题格式

```

```

## 洞察性结论规范

### 核心原则

报告中的每个数据点都应该回答：**"这个数字对业务意味着什么？"** 读者应该能在不翻数据表的情况下，仅通过读标题和 bullet 就能把握全部核心信息。

### Bullet 三要素格式

每个正向指标的 bullet 必须包含三个要素，缺一不可：

```
● {指标名}：净提升{值}{单位}(+{百分比}%)，{业务洞察短句}
```

示例（来自实际报告）：
```
● 观看时长(min)：净提升76.78分钟(+17.9%)，用户更喜好平台内容
● 观看天数：净提升0.59天(+11.9%)，回访更稳定
● 观看主播数：净提升2.53个(+20.5%)，探索意愿增强
● 付费转换率：净提升1.42pp(+11.74%)，付费意愿增强
```

### 业务洞察措辞库

根据指标含义和方向，选择最贴切的业务解读：

| 指标类型 | 正向解读 | 负向解读 |
|---------|---------|---------|
| 活跃类时长（观看时长等） | "用户更喜好平台内容" | "用户内容消费时长有所下降" |
| 活跃类频次（观看天数、活跃天数） | "回访更稳定" | "用户回访频次有所减少" |
| 探索类（主播数、游戏数） | "探索意愿增强（更多元的内容消费）" | "探索意愿有所收缩" |
| 付费转化率 | "付费意愿增强"、"更多用户愿意付费" | "付费转化有所下降，需关注付费引导" |
| ARPPU | "付费深度提升"、"付费用户消费升级" | "付费用户消费深度下降（需排除稀释效应）" |
| 原始付费金额不显著时 | 不写"不显著"了事 → 写"付费金额{正向/负向}结果不显著（p值高于临界值），没有出现活动后用户流失、时长下滑、付费明显下降的情况" |

### DID核心结论段自动生成规则

这是每一节"关键效果指标"下的第一段文字，必须是一句综合性的判断而非数据罗列。生成逻辑：

```python
# 1. 统计正向显著指标
lt_pos = [指标 for 指标 in LT_OUTCOMES if DID>0 and p<0.05]
ltv_pos = [指标 for 指标 in LTV_OUTCOMES if DID>0 and p<0.05]
lt_neg = [指标 for 指标 in LT_OUTCOMES if DID<0 and p<0.05]

# 2. 按模式生成
if len(lt_pos) >= 3:
    lt_verdict = f"活动可作用于用户{维度A}、{维度B}和{维度C}"  # 选top3
elif len(lt_pos) >= 1:
    lt_verdict = f"活动对用户{维度X}有正向作用"
else:
    lt_verdict = "活动在各活跃维度均未表现出统计显著的净效应"

if ltv_pos:
    ltv_verdict = "在付费{指标}上有显著拉升" if pay_rate显著 else "在付费{指标}上有正向作用"
    # ★ 对于LTV，优先引用pay_rate的结论（最可靠），ARPPU次之
elif lt_neg:
    ltv_verdict = "但在付费维度出现负向变化，需关注"
else:
    ltv_verdict = "付费维度无显著变化（原始金额CV过高，建议参考付费转化率）"

core_conclusion = f"DID核心结论：{lt_verdict}；{ltv_verdict}。"
```

### 不显著指标的语境化处理（★ 关键）

对于不显著但用户关心的指标（尤其是付费金额），不能只写"p=0.45，不显著"——这会让读者觉得"分析没做完"。正确的做法是给上下文：

| ❌ 错误写法 | ✅ 正确写法 |
|-----------|-----------|
| "付费金额 DID=-12.3元，不显著" | "付费金额负向结果不显著（p值高于临界值），没有出现活动后用户流失、时长下滑、付费明显下降的情况" |
| "ARPPU 不显著" | "ARPPU未见统计显著变化——活动既未提升也未损害付费用户的消费深度" |
| 只列出正向指标，不提不显著的负向指标 | 正向列完后加一段："无任何显著负向指标"，消除读者的隐性担忧 |

### 多模块报告的综合结论

当全量 + 子人群两个模块都完成后，在报告最顶层写一段 1-2 句的综合结论。结构为：
- 前半句：全量样本的核心发现
- 后半句：子人群的核心发现
- 两句之间用分号连接

示例：
> "不朽杯打卡活动可以正向拉动参与用户的观看时长、观看天数、活跃天数和探索广度，在付费维度，活动显著提高了付费转换率；对于参与不朽杯打卡活动的Dota2兴趣用户，活动可以正向拉动参与用户的观看时长、观看天数、活跃天数和和探索广度，在付费上付费转换率也呈显著正向提升。"

这段结论不是分析完才写的——而是 DID 数据产出后，由代码根据 significance 和 direction 自动生成的。生成规则：各模块取 top 3-4 正向显著维度的维度概括词，串联成句。

## 硬编码默认值与可调范围

以下参数为已验证值，通常无需修改但可根据实际情况调整：

| 参数 | 默认值 | 可调范围 | 调整建议 |
|------|--------|---------|---------|

## 常见问题排查

| 现象 | 可能原因 | 排查方向 |
|------|---------|---------|
| 匹配率 < 50% | 卡钳过严或实验组与对照组差异太大 | 放宽 CALIPER → 0.1 或 0.15；检查PS分布是否有足够重叠 |
| SMD 不通过（>0.1） | 某些特征两组先天差异大 | 考虑加入该特征的二次项/交互项；或改用 CEM 粗化精确匹配 |
| 所有 DID 都不显著 | 样本量不足或效应确实小 | 检查每组样本量（建议≥500）；考虑扩大时间窗口 |
| Excel 打开中文乱码 | 编码问题 | 确认 CSV 用 utf-8-sig；xlsx 用 openpyxl 写而非 pandas to_excel |
| 中位数和均值方向矛盾 | 稀释效应 | 读 `references/ltv-methodology.md` 的稀释效应章节 |
| f-string 语法错误 | 逗号格式化字符冲突 | `{var:,}` 在嵌套 f-string 中易报错，先用临时变量 format |
