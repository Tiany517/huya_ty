## 必须保留的解释边界

1. PSM 只是在已观察协变量上改善平衡，不能消除未观察混杂。DID 还依赖平行趋势等假设；现有归档材料没有给出足以证明平行趋势的证据。
2. 历史报告中的“SMD 均小于 0.1，所以后续差异完全由活动导致”和“因果结论可靠”属于过强表述。可报告的是在既定 PSM/DID 设计下的估计值，不能自动升级为已验证的真实因果效果。
3. 2026-06-12 旧版报告曾同时写“全部 SMD < 0.1”和“最大 |SMD| = 0.2028”，版本已被 6 月 15 日重做版替代，不作为最终结果。
4. 中位数表的显著性文字存在与 p 值不一致的情况，例如小 p 值仍标“不显著”。新电脑复用前必须从 p 值、效应方向和统一阈值重新生成标签，不能照抄旧报告。
5. 部分报告把付费转化率的单位写成“天”；正确单位是百分点。
6. 1 天曝光前后各 7 天的设计容易受当日波动和同期事件影响。曝光结果应表述为短窗口估计，不宜外推为长期影响。

完整版本与错误模式见 `methodology/report-revisions.md`。

## 校验

在仓库根目录运行：

```powershell
python projects/buxiucup-popup-psm/scripts/validate_buxiucup_project.py
```

校验脚本是只读检查：确认关键文件存在、CSV 不含用户级表头、XLSX sheet 名称和关键 DID 数值正确、DOCX 中的样本数和最大 SMD 与盘点一致，并记录仍存在的中位数显著性标签异常。硬校验失败会返回非零退出码。

## 迁移边界

原目录约 10.89 GB、195 个文件。本仓库没有上传约 9.71 GB 全量用户行为 CSV、约 831 MB 未参与用户明细、约 320 MB 打卡分析源 CSV、曝光分析用户级源 CSV、用户 ID、账户级曝光 / 点击明细、全部历史迭代图、临时文件和缓存。保留的是三套最终报告、匿名汇总、关键匹配图、核心 SQL 和最终分析脚本。

## 新电脑复用步骤

1. 先读本说明和 `methodology/report-revisions.md`，确认三个分析问题不可混用。
2. 按 `instructions/sql-validation-workflow.md` 先恢复结果契约、源表粒度、分区、单位和匹配设计。
3. 脚本中的 Windows 源路径和 CSV 文件名来自旧电脑；重跑前改为新电脑路径，并重新确认数据字段和分区。
4. 先运行自动校验，再按新数据重算样本量、匹配率、SMD、平行趋势、DID、p 值和标签；报告、XLSX、CSV 三方必须对账。
5. 如果无法运行独立复算，只能标记“历史上传结果”或“校验未执行”，不能标记为已验证。
