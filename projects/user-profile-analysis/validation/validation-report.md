## 结果契约

- 分析对象：设备用户画像、斯诺克拉新画像、世锦赛观看画像和 10 分钟以上观看画像。
- 结论类型：描述性画像和 TGI 差异；不据此声明因果、推荐增益或稳定人群身份。
- 输入：TGI 聚合 CSV、4 份 DOCX、3 份 SQL、2 份含用户级工作表的 XLSX、2 份含标识的 CSV。
- 数据粒度：TGI 为“队列 × 画像维度 × 画像值”的聚合；聚类为“抽样用户 × 聚类标签”后转成组内汇总。
- 输出粒度：匿名聚合；不保留用户标识和用户行。
- 关键分母：设备 172,312 / 390,718 / 145,179；斯诺克 1,072 / 2,676；世锦赛观看 208,206 / 366,543；10 分钟以上观看 192,764 / 395,788。
- 完成条件：分母闭合、TGI 独立复算、双语附件对齐、用户标识扫描、源哈希、SQL 静态审查和报告冲突核查均留下证据。

## 风险画像与可反驳预期

本次高风险点包括：画像日表多天快照、不同产品枚举、两组日期窗不等、TGI 小分母、KMeans 抽样与标签可复现性、多个报告版本，以及用户级文件被误传。

预先设定的反例是：

1. 若 TGI 分母在不同画像维度发生变化，说明队列或重复行计数错误。
2. 若聚类人数占比相加不等于 100%，说明报告或汇总混用了不同样本。
3. 若报告聚类总人数与可用的处理样本不同，则报告聚类不能由当前文件复现。
4. 若源 SQL 的产品枚举不一致或 CTE 未定义，则现存 CSV 不能仅凭源 SQL 重建。
5. 若仓库 CSV、DOCX 或 JSON 出现 `mobile/<hash>` 或 `user_ukey` 表头，则隐私边界失败。

这些反例已经实际用于校验，而不是只在文档中描述。

## 报告与数据冲突

1. 旧设备报告把 12 个聚类全部显示为 `100.0%`。聚类人数本身正确，但占比应为人数 / 50,000。
2. 斯诺克报告写 3,767 条用户记录，TGI 分母为 1,072 + 2,676 = 3,748；差额 19 的来源没有留存。
3. 斯诺克 TGI 表音乐 App 目标占比为 `56.25%`；报告另一个叙事段写 `63.1%`。
4. 10 分钟以上观看报告把 192,764 名观看用户写成“大型赛事拉新的用户”；该队列是观看时长达到 10 分钟的用户，不是新用户。
5. 保留的斯诺克处理样本有 1,086 行、1,074 个唯一标识和 12 条重复标识行，不能复现报告的 n=1,072 聚类。
