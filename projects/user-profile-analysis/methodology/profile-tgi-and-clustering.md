| --- | ---: |

保留的聚合 TGI 表可按这三组重建两两比较。原始设备 CSV 却只有 178,432 行，其中 iOS 178,412 行、Android 20 行、178,244 个唯一标识，和三组全量不一致。因此它只能作为一个不完整且敏感的历史导出，不是本项目的全量源。

### 1.2 斯诺克拉新画像

源 SQL 用体育赛事主播登记表和用户观看会话表识别 2026-04-18 至 2026-05-06 的观看者，再关联 2026-04-18 至 2026-05-04 的画像日表。聚合 TGI 表的目标组为 1,072 人、对照组 2,676 人。

注意：存储 SQL 的对照组窗口比目标组少 05-05 和 05-06 两天，目标组注释还把 2026 写成 2025。这两个问题未修正，结果只作为历史聚合保留。

### 1.3 世锦赛观看用户

完整观看组为 208,206 人，对照组 366,543 人；10 分钟以上观看组为 192,764 人，对照组 395,788 人。聚合文件没有随附完整的日期、来源表和用户筛选 SQL，因此只能复核组内占比与 TGI 算术，不能独立证明来源队列。

## 2. TGI 口径

对每个画像维度和取值分别计算：

```text
TGI = (目标组中该取值人数 / 目标组总人数)
      / (对照组中该取值人数 / 对照组总人数) * 100
```

同一维度内，各取值人数之和应等于固定组分母；目标组和对照组占比分别应闭合到 100%。TGI 表使用一位或两位小数展示占比，因此从展示值复算 TGI 允许约 0.16 的四舍五入误差。

本次校验结果：

- 7 份设备/斯诺克/世锦赛 TGI 表均通过分母、占比闭合和公式复算。
- 所有维度都回到固定组分母，没有发现把多行展示重复计入分母的现象。
- 最大展示占比闭合误差为 `0.05` 个百分点。
- 最大 TGI 复算差为 `0.05`。

TGI 不是显著性检验。极小占比、极小样本、20、40 或 200 等边界值不能直接写成强业务差异；应同时核对人数、分母、缺失结构和多重比较。

## 3. KMeans 与 PCA

### 3.1 设备三组

原报告说明每组独立做 KMeans、K=4，并从每组抽取 50,000 用户。抽样聚类标签工作表均可验证为 50,000 行、50,000 个唯一用户标识。旧报告把每个聚类占比都显示成 100%，但四个聚类人数相加本身就是组内样本总量；匿名汇总使用“聚类人数 / 50,000”重新计算占比。

原报告轮廓系数为：鸿蒙 `0.1156`、安卓 `0.1180`、苹果 `0.1685`。这些值偏低，聚类更适合描述差异，不适合作为稳定分群标准。源目录没有保留完整特征工程、标准化、随机种子和聚类脚本，无法重建原标签。

### 3.2 世锦赛 10 分钟以上观看用户

报告说明使用 StandardScaler、KMeans K=4，从目标组 192,764 人中抽取 50,000 人；K=4 轮廓系数 `0.1434`，PCA 两维累计解释方差约 `30.1%`。聚类标签工作表为 50,000 行、50,000 个唯一 user_ukey。

轮廓系数低于 0.2，说明聚类结构弱；聚类名称只能作为本次分析的可读标签。完整目标群体是否同分布、抽取方法是否随机、特征中未知值的处理是否合理，源目录没有足够证据。

### 3.3 斯诺克用户聚类

报告写 K=4、n=1,072、轮廓系数 `0.3237`。保留的 `processed_data_v2.csv` 包含 1,086 行、1,074 个唯一伪匿名标识和 12 条重复标识行，聚类编号 0–3 的人数与报告四类人数不同。当前目录无法说明这 1,086 行是何种抽样、为何有重复，以及报告聚类是如何从另一批 1,072 人得到。

因此报告中的四类画像、轮廓系数和聚类结论只能作为历史材料，不能标记为已验证。匿名附件额外保留了这套不勾稽样本的描述统计，并明确写明用途。

## 4. SQL 静态风险

| SQL | 已确认问题 | 业务影响 |
| --- | --- | --- |
| `鸿蒙安卓和苹果用户的画像.sql` | 过滤 `huya_andriod`，CASE 识别 `huya_android` | Android 队列不可复现 |
| `鸿蒙安卓和苹果用户的画像.sql` | 31 天画像日表只按用户关联，最后仅 `distinct` | 用户可能有多个变化中的画像快照；缺少固定的用户级快照规则 |
| `观看过世锦赛和未观看过世锦赛的画像.sql` | 目标窗口 05-06，对照窗口 05-04 | 两组观察机会不同 |
| `观看过世锦赛和未观看过世锦赛的画像.sql` | 2026 日期旁注释为 2025 | 赛事版本语义错误 |
| `观看过世锦赛且单日观看时长最长的用户.sql` | 引用未定义 CTE | 第二个分支不能执行 |
| `观看过世锦赛且单日观看时长最长的用户.sql` | 文件名写单日，代码按全期间求和 | 指标与业务问题不一致 |
| `观看过世锦赛且单日观看时长最长的用户.sql` | 两个分支共用同一 `user_type` | 无法区分目标组和对照组 |
| `观看过世锦赛且单日观看时长最长的用户.sql` | `watch_duration` 单位未确认 | 排序是否有效尚未证明 |

## 5. 报告与结果的正确使用顺序

1. 先看 `artifacts/anonymous-summary/tgi/` 中对应队列的分母和人数。
2. 再看 `validation/validation-report.md` 是否把该结果标为可复算、已知问题或未执行。
3. 最后阅读历史 DOCX 的业务解释；报告中的聚类占比和“拉新”等措辞不能覆盖底层数据证据。
4. 若要把结果用于新活动、投放或产品决策，必须先修复 SQL 并重新取数，完成固定快照、共同窗口、字段单位、独立分母和报告四方对账。
