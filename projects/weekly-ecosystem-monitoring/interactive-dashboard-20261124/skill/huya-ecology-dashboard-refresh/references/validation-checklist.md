# 刷新验收清单

## 输入

- [ ] 当前期、对比期、实际最新分区已写明。
- [ ] 三个核心 CSV 文件名、周期和内容一致。
- [ ] header 完整，UTF-8 可读，中文无乱码。
- [ ] `week_start` 为连续周一，日表日期在周表范围内。
- [ ] 输入 SHA-256 已记录。
- [ ] 未在文件或日志中写入平台凭据。

## 数据

- [ ] 已从源表独立复算，并生成 `accuracy_reconciliation_<run>.md`。
- [ ] 当前期和对比期均完成抽样，至少覆盖总盘、头部、尾部和 3 个公会。
- [ ] 品类、主播周表、主播日表的行数、唯一键、日期集合与源表一致。
- [ ] 整数人数、UID、RoomID、日期和周起点精确一致；浮点金额/时长按声明精度对账。
- [ ] 每个抽样节点都记录源表值、CSV 值、差异和结论，未只写“已核对”。
- [ ] 品类日表 `(dt, gameid)` 唯一。
- [ ] 主播周表 `(week_start, gameid, guild_name, luid)` 唯一。
- [ ] 主播日表 `(dt, luid)` 唯一。
- [ ] 核心表行数大于 0，metadata diagnostics 与实际数组长度一致。
- [ ] 昵称覆盖率达到 99%，RoomID 覆盖率达到 90%。
- [ ] 开播主播数满足品类 <= 内容大类 <= 平台；主播周 `live_days` 在 0–7；主播日 `is_live` 仅为 0/1。
- [ ] 数值有限；无 NaN/Infinity。
- [ ] 月份缺周产生“数据不足”，不是 0 或伪造环比。
- [ ] 互动人数大于 DAU 的记录作为警告保留，不强行截断。
- [ ] 赛事 CSV 缺失时 `eventStatus=pending`；有 CSV 时 `ready` 且行数大于 0。

## 成品

- [ ] `validation_report_<run>.json` 为 `passed`。
- [ ] `run_manifest_<run>.json` 含输入/输出路径、字节数、SHA-256、行数和命令。
- [ ] 浏览器冒烟检查通过：标题、Top20 渲染、loading 清空、进程退出 0。
- [ ] 人工抽查首屏、月度、季度、自定义时间、维度增删/排序、公会/层级/主播下钻。
- [ ] UID、RoomID、昵称、模糊词搜索能返回候选。
- [ ] 单主播模式隐藏维度搭建器和多层表。
- [ ] 多层结构默认收起，展开后可逐层下钻。
- [ ] 移动端无明显遮挡或横向溢出。

## 发布

- [ ] 正式文件名包含周期或运行版本。
- [ ] 覆盖旧成品前已经明确授权，并保留可恢复副本。
- [ ] 交付说明写明数据止期、赛事状态、交互口径警告和浏览器验证状态。
