# 生态监控看板全流程与表格口径

版本：2026-11-24

## 1. 结论

当前看板是一份可直接打开的单文件 HTML，数据源来自生态健康日表、品类维表、主播日维表和游戏支付明细。它已支持全品类、内容大类、公会、主播层级、主播任意顺序下钻，支持周/月/季/年/日/自定义时间对比，以及 UID、RoomID、昵称模糊搜索。核心指标新增“开播主播数”。

当前数据止于 2026-11-23；主播周归因覆盖 W42–W47（2026-10-12 至 2026-11-22）。赛事支付属性 SQL 尚未形成有效产出，因此赛事筛选不能用于 DAU、归属用户和互动对比。

## 2. 需求演进记录

1. 起点：读取 `生态监控模板_1019.xlsx`、`结果输出_1013.xlsx` 和旧周报 SQL，确认旧版主要围绕固定六品类：英雄联盟、王者荣耀、CS2、体育、户外、无畏契约。
2. 看板化：参考 `game_revenue_dashboard.html` 的对比和贡献值形式，并保留旧周报指标。
3. 动态 Top20：每层归因不固定主播，按当前期/对比期和当前下钻范围动态列出变化贡献最高的 Top20。
4. 全品类扩展：取消固定六品类，接入内容大类“游戏 / 娱乐（秀场）/ 娱乐（非秀场）/ 未匹配”。
5. 任意维度：维度可增删、拖动排序，不再固定“公会→层级→主播”的顺序。
6. 时间能力：增加周、月、季、年、日和自定义当前期/对比期；支持月对月，而不只周对周。
7. 主播专项：支持 UID、RoomID、昵称和模糊词搜索；选中后隐藏维度搭建器及多层表，直接显示该主播的 DAU、归属用户、流水、互动人数和互动率趋势。
8. 可解释性：修复全平台 DAU 被主播明细放大、月份缺周被按 0 计算、贡献值缺失等问题。
9. 资源化：把数据构建脚本参数化，做成 `huya-ecology-dashboard-refresh` Codex skill，支持另一台电脑替换 CSV 后重建、对账和浏览器冒烟。
10. 开播供给：新增“开播主播数”，按当天 `is_live=1` 的 `luid` 去重后计算周期日均；品类、内容大类和平台使用日级精确去重，公会、层级和主播使用 `live_days`。

## 3. 数据流

```text
生态健康日表 category='品类整体'
  -> 品类日表 CSV
  -> dashboard JSON 的 categoryDaily
  -> 平台/大类/品类趋势和核心指标

生态健康日表 category='主播明细' AND is_live=1
  -> 平台、内容大类、品类开播主播数
  -> categoryDaily 的 liveAnchors、groupLiveAnchors、totalLiveAnchors

生态健康日表 category='主播明细'
  + 主播日维表（公会、昵称、RoomID、评论数、评论人数）
  -> 主播周表 CSV
  -> dashboard JSON 的 anchorWeekly
  -> 公会/层级/主播下钻、live_days 和动态 Top20

主播日表 SQL
  -> 主播日表 CSV
  -> dashboard JSON 的 anchorDaily
  -> 单主播精确日趋势和 is_live

支付明细 + 90 天赛事观时属性 SQL
  -> 赛事支付 CSV（当前缺失）
  -> dashboard JSON 的 eventRevenueDaily
  -> 仅在 ready 后启用赛事支付筛选

CSV -> 参数化 builder -> JSON -> 注入 HTML 模板 -> 单文件 HTML -> 数据对账 + 浏览器冒烟
```

## 4. 取数与处理步骤

### 4.1 品类整体

- 源表：`zhgametemp.zty_category_ecology_health_daily_d_i_0827_v1`。
- 过滤：`category='品类整体'`。
- 维表：`gamelive.dim_huya_game_d_a`。
- 粒度：`dt × gameid`。
- 作用：全平台、内容大类、各品类 DAU、归属用户、流水、打赏人数、ARPPU、人均观时、开播主播数和趋势。
- 原则：全平台 DAU 直接取品类整体口径，不把主播明细相加回全平台。
- 开播主播数：从 `category='主播明细' AND is_live=1` 按日期和 `luid` 去重，再分别汇总到品类、内容大类和全平台。

### 4.2 主播周归因与公会

- 主表：健康日表 `category='主播明细'`。
- 维表：`gamelive.dm_huya_ayyuid_detail_day`，按 `dt + gameid + luid` 补昵称、公会、RoomID、评论数 `com_cnt`、评论人数 `com_ucnt`。
- 清洗：排除空 UID、`0`、`-1`；排除昵称以 `#` 开头和“未归属主播”的异常行。
- 粒度：`week_start × gameid × guild_name × luid`。
- 作用：公会、主播层级、主播归因、互动指标和 `live_days`。`live_days` 为当前周内当天 `is_live=1` 或 `live_mins>0` 的去重日期数。

### 4.3 主播日级专项

- 与周表使用相同的健康日表、维表和过滤条件。
- 粒度：`dt × gameid × luid`。
- `is_live` 保留主播当天是否开播，用于开播供给专项检查。
- HTML 只收录当前周范围内满足“归属 DAU >=10 或流水 >=1 元或互动人数 >=10”的主播，以控制文件体积。
- 未收录主播不代表全平台没有该主播，仅表示不在当前看板专项覆盖范围。

### 4.4 构建与压缩

- 品类名称、品类索引、公会索引和主播索引从 CSV 建立。
- 数值统一转数值并压缩小数，字符串保留 UID 和 RoomID。
- 周列表根据主播周表的 `week_start` 自动推导；构建器要求全部是周一、连续 7 天、无缺周。
- 最新分区根据品类日表的 `dt` 自动推导，也可显式传入。
- 输出 JSON 注入 `dashboard_template_multidim.html`，形成不需要额外接口的单文件 HTML。

## 6. 看板交互口径

### 6.1 周期

- 日、周、月、季、年、自定义均支持当前期和对比期。
- 周期选择可以是月对月、季对季、年对年，也允许自定义两个区间。
- 周数据不足两侧完整覆盖时，非周对比只做近似，并显示覆盖提示；月份缺周时显示“数据不足”，不按 0 计算。
- 趋势图只展示当前期和对比期覆盖时间桶，不完整时间桶加 `*`。

### 6.2 维度栈

- 用户可增删、拖动任意维度：内容大类、品类、公会、主播层级、主播。
- 单层表显示当前范围下一层 Top20。
- 多层结构表按当前维度顺序递归展开，默认收起；点击节点继续下钻。
- 父层贡献以直接父范围的变化为分母；总盘贡献以全平台变化为分母。
- 静态截图不能代表全量品类，必须使用 HTML 的实际筛选结果。

### 6.3 主播搜索

- 支持 UID、RoomID、昵称。
- 支持规范化文本、前缀、包含和子序列模糊匹配，例如忽略大小写、空格或拆分字符。
- 搜索完成后列出候选，用户必须选择一个主播进入专项模式。
- 专项模式隐藏维度搭建器和多层结构表，只保留该主播卡片和趋势。

## 7. 表格与字段口径

### 7.1 两期核心指标

| 字段/指标 | 口径 |
|---|---|
| 当前期日均 | 当前期有数据日期的自然日均 |
| 对比期日均 | 同一指标在对比期的自然日均 |
| 绝对变化 | 当前期日均 − 对比期日均 |
| 变化率/环比 | 绝对变化 ÷ 对比期日均 |
| 观看 DAU | 健康日表 `dau` 日均 |
| 归属 DAU | `attribution_user_cnt` 日均 |
| 打赏流水 | `daily_revenue` 日均 |
| 打赏人数 | `daily_pay_user_cnt` 日均 |
| ARPPU | 打赏流水 ÷ 打赏人数 |
| 人均观时 | 有观看记录日期的 `avg_view_mins` 平均 |
| 互动人数 | `interaction_user_cnt` 日均 |
| 互动率 | 互动人数 ÷ 观看 DAU |
| 开播主播数 | 当天 `is_live=1` 的 `luid` 去重数再取周期日均；开播判定为 `is_live=1` |

### 7.2 单层 Top20

字段：层级/节点、对比期日均、当前期日均、日均变化、环比、父层贡献、总盘贡献、互动率、互动人数。

- 日均变化 = 当前期日均 − 对比期日均。
- 环比 = 日均变化 ÷ 对比期日均。
- 父层贡献率 = 节点日均变化 ÷ 当前筛选范围日均变化。
- 总盘贡献率 = 节点日均变化 ÷ 全平台日均变化。
- 负向拖累按变化值升序；正向拉动按变化值降序；变化贡献按绝对值降序。
- Top20 合计不一定等于 100%；榜单只展示最大贡献项。
- 当前期或对比期覆盖不足时，变化和贡献显示“数据不足”或 `—`。

### 7.3 多层结构表

- 递归展开当前维度栈。
- 父层贡献以直接父路径为分母。
- 总盘贡献以整体根节点为分母。
- 不同路径下主播、观看用户和互动用户可能重复，不能直接相加成独立用户总量。

### 7.4 维度字典

| 维度 | 口径 |
|---|---|
| 内容大类-游戏 | `game_label='游戏'` |
| 内容大类-娱乐（秀场） | `game_label='娱乐'` 且 gameid 为 `1663/2165/4079` |
| 内容大类-娱乐（非秀场） | 其余 `game_label='娱乐'` |
| 未匹配 | 最新品类维表无法匹配 |
| 公会 | `dm_huya_ayyuid_detail_day.cname`，空值为“无公会” |
| 主播层级 | 运行窗口整体平均 ACU；头部 `>=2000`，腰部 `100 <= ACU < 2000`，尾部 `<100` |
| 赛事用户 | 支付日前 90 天，赛事主播日期观时 ÷ 同游戏总观时 `>=70%` |

## 8. 重要限制

1. 赛事支付 SQL 尚未回刷，赛事筛选当前不可用于核心流量和互动指标。
2. 互动人数可能大于主播 DAU，因为跨场次和跨主播人数没有全量去重；互动率只能用于相对趋势，不能直接解释为独立用户渗透率。
3. 各品类、公会和主播的观看/归属/互动用户会重叠，不能把分组人数直接相加为全站人数。
4. 主播层级阈值为当前 W42–W47 的平均 ACU 门槛；后续刷新若改变分层口径，必须同步更新模板并记录版本。
5. 主播日表只覆盖活跃度达到阈值的主播，未搜到某个主播时要先确认是否在专项覆盖范围。
6. ARPPU 不能由分组 ARPPU 求简单平均，必须回到总流水和总打赏人数重新计算。

## 10. 另一台电脑上的更新流程

### 10.1 数据同学交付

只交付三个核心 CSV 和可选赛事 CSV，列名见 `skill/huya-ecology-dashboard-refresh/references/input-contract.md`。

### 10.2 Codex 执行

安装 `skill/huya-ecology-dashboard-refresh` 后调用该 skill，或直接运行资料包内脚本：

```bash
python scripts/refresh_dashboard.py \
  --category-csv <category_daily.csv> \
  --anchor-weekly-csv <anchor_weekly.csv> \
  --anchor-daily-csv <anchor_daily.csv> \
  --template assets/dashboard_template_multidim.html \
  --output-dir <new_run_dir> \
  --run-name <YYYYWww> \
  --smoke-test
```

### 10.3 必须检查

1. 确认最新分区、当前期和对比期，记录实际数据止期。
2. 输入 header、非空、周一、连续周和长 ID 字符串格式。
3. 三张表唯一键、行数、日期集合和维度集合。
4. 从源表独立复算品类、公会和主播样本；当前期与对比期均覆盖，每个抽样节点记录源表值、CSV 值、差异和结论。
5. 开播主播数从 `category='主播明细' AND is_live=1` 的 `luid` 去重复算；核对 `live_days` 在 0–7 和 `is_live` 仅为 0/1。
6. `accuracy_reconciliation_<run>.md` 结论为 `passed`。
7. metadata diagnostics 与实际数组行数一致。
8. 昵称覆盖率达到 99%，RoomID 覆盖率达到 90%，无 NaN/Infinity。
9. 赛事状态 `ready/pending` 与数据一致。
10. HTML 可渲染、Top20 已出现且 loading 清空。
11. 人工抽查时间切换、自由维度下钻、贡献值、开播主播数和主播搜索。
12. 输出哈希、行数和运行命令写入运行清单。

## 11. 复盘结论

当前版本可以用于 MVP 业务讨论和主播/公会归因，但赛事用户维度仍是半成品。后续正式化优先级建议：先回刷赛事支付属性并验证，再固化每周数据交付和自动发布；在此之前，不应用赛事筛选给出流量或互动结论。
