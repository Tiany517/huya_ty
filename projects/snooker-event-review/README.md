# 斯诺克赛事专题迁移说明

## 项目目的

本目录用于把“斯诺克赛事与世锦赛拉新、留存、转化、视频偏好、画像和最终汇报”整理成新电脑可直接阅读和继续工作的归档。重点不是重新运行一套无法回溯的历史分析，而是保存：

1. 已交付的最终文件快照；
2. 可复用的 SQL 和画像脚本；
3. 关键匿名汇总、指标定义、已知缺陷和验证证据；
4. 从 GitHub 相对路径到项目内容的清晰地图。

原始项目目录保持不动。仓库不上传用户级明细、UID、`user_ukey`、昵称或大体积身份工作簿。

## 指标定义与不可混用边界

### 世锦赛受众与漏斗

`世锦赛受众与漏斗.csv` 保留原交付表的事件期汇总口径。这里的中英文“看赛用户”分别报为 403.6454 万和 631.2202 万；它们是原表事件期日均汇总结果，不是整段赛事区间内去重后的 UV，不能直接与另一个区间去重口径相加或替换。

拉新用户、视频观看用户、星秀观看用户、打赏用户也应按逐赛季和用户组分别读取。所有人数单位均为“万”。

### 视频/直播独立覆盖率

`世锦赛拉新用户视频直播覆盖率.csv` 来自独立的最终交付 CSV，与上面的日均漏斗不是同一条可加总链路。视频覆盖率和直播覆盖率来自各自单独的分母，不能把两个比例直接相加为 100%；两者是否存在用户交集，应以原 SQL 和底层用户表继续确认。

### 拉新付费

`tipping_rate_pct` 为打赏用户数除以拉新用户数；“总打赏金额”单位为万元人民币；人均值分为“除以全部拉新用户”和“除以实际打赏用户”两列，不能混用。

### 赛事到世锦赛留存

每行是“基准赛事赛季 × 阶段 × 目标赛事”。同一赛事赛季的各阶段应共用基准期拉新用户分母；D7/D14 或其他多窗口并不在本表新增行。留存率分母和分子均为人数，不能把复制后的多窗口行相加。

### 画像聚类

画像原始处理样本为 3,638 条，按 `user_ukey` 去重后为 1,086 人。四类人数分别为 107、199、358、422，合计 1,086；占比合计 100%。原始用户级特征文件没有上传。

### 画像

## 已确认的质量问题

1. 2025 世锦赛最终 CSV 和工作簿页签内嵌为“2026 世锦赛期间”，但数值实际位于 2024/25 对照槽位。本项目按页签位置识别赛季，并保留源标签。
2. `LPL1_LPL2_王者_斯诺克_转化情况.csv` 实际内容是 2025/2026 世锦赛视频与直播占比，不是文件名承诺的四赛事转化比较；已从标准化分析隔离，仅保留来源证据。
3. 上海大师赛基准人数存在两组分母：2024/25 为 91,295 对 87,485；2025/26 为 278,071 对 265,175。留存率方向可参考，绝对留存人数在业务字典确认前不能混用。
4. 画像中的 33% 疑似虚假注册尚未获得风控证据，保持高风险待验证状态。
5. 最终汇报中的 ROI 0.9 和 +7.5% 无法由保留的匿名工作簿和 CSV 独立复算，只能写成历史汇报原文。
6. 秀场打赏率工作簿的“变化”行没有统一使用百分点，本项目不使用该变化行下结论。
7. 两个超大原始工作簿、含 `user_uid` 的 19,456 行留存 CSV 和含 `user_ukey` 的画像特征 CSV 未上传；GitHub 包不能单独重建这些用户级分析。

完整字段化版本见 `artifacts/zh/质量问题.csv`。

## 复现命令

在仓库根目录执行，`<source-root>` 指向本机原始斯诺克专题目录：

```powershell
python projects\snooker-event-review\scripts\build_snooker_package.py --source-dir "<source-root>"
python projects\snooker-event-review\scripts\verify_snooker_package.py --source-dir "<source-root>"
```

构建脚本只读取源目录并写入本仓库的 `projects/snooker-event-review/`；不覆盖原始文件。验证脚本重写匿名校验结果和汇总状态文件，不修改源目录。

## 新电脑接手顺序

1. 先读本页的“指标定义与不可混用边界”和“已确认的质量问题”。
2. 用 `artifacts/zh/世锦赛受众与漏斗.csv`、`世锦赛拉新付费.csv`、`赛事到世锦赛留存.csv` 重新核对本文关键数字。
3. 需要追 SQL 时，先从 `sql/source/` 查同名或近似口径，再查 `artifacts/zh/来源清单.csv` 中的原始相对路径和哈希。
4. 需要复查最终交付时，从 `artifacts/final-delivery/` 读取完整快照，但不要假设文件内标签一定正确，先套用 7 项质量问题。
5. 需要继续画像时，先确认是否拥有受控环境中的用户级源文件；仅靠本仓库只能复核匿名聚类结果，不能重跑用户级特征。
6. 正式修改 SQL 或画像结论前，遵守仓库根目录 `instructions/AGENTS.md` 的结果契约和验证工作流。
