# 王者主播离开影响 SQL

| SQL | 用途 | 必要参数 |
| --- | --- | --- |
| `attributed-dau-rolling-baseline.sql` | 计算一个对象从 2025-01-01 至 2026-04-30 的日归因 DAU，并生成六/十二个月滚动均值 | `{{TARGET_STREAMER_LUID}}` |
| `related-anchor-overlap.sql` | 计算一个相关对象的归属用户中，同日在目标对象直播间出现过的用户数 | `{{RELATED_STREAMER_LUID}}`、`{{TARGET_STREAMER_LUID}}` |

## 运行前检查

1. 用获准的主播 ID 替换全部 `{{...}}` 占位符；仓库故意不保存真实 ID。
2. 确认目标日期分区存在。日归因 SQL 的时间窗是 2025-01-01 至 2026-04-30；重合 SQL 是 2026-04-01 至 2026-05-31。
3. 确认两个源表在当前环境的访问权限和字段类型；`ukey` 与 `user_ukey` 的字符串/数值类型必须一致，必要时显式转换。
4. 检查平台枚举。直播会话过滤中的 `huya_andriod` 拼写来自原 SQL，除非上游字典确认，否则不要擅自改成 `android`。
5. 独立核对输出：日归因用户按 `dt` 唯一；相邻月份有同一用户属于正常现象；六/十二个月窗口分别包含当月和之前 5/11 个月。
6. 原月均值 SQL 在两个整数之间直接相除，部分引擎会截断小数；迁移副本把分子乘 `1.0` 以保留小数。新旧版本若差异只出现在小数位，应按此变更解释，并重新确认历史 PPT 是否仍使用截断值。
7. 当前没有在迁移环境执行这些 SQL，因此状态是“去标识化、待验证”，不能写成“已验证结果”。
