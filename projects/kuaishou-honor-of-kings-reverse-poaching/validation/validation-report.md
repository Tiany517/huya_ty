## 4. 独立复算与纠错

1. 从原始 CSV 独立重建主播月 ACU 和日均开播分钟，不读取工作簿中的月度结果作为输入。
2. 从工作簿读取候选 ID 集合，只用于比较候选集合，不参与规则计算。
3. 早期工作簿、旧版工作簿和 V2 工作簿的月度明细分别与原始 CSV 重建结果逐行对账。
4. 先前草稿曾判断“四个月 50% 情景为 7/8、1 人换入、1 人换出”；本次独立执行得到规则 8 人、工作簿 8 人、交集 8 人，原判断已被推翻并从项目结论中删除。
5. 预测表有 46 行对 45 个主播月；重复行来自同一主播月，三组预测指标完全相同。脚本先验证重复值一致，再按主播月去重；若未来出现冲突会停止。

## 5. 未验证事项

1. 没有这批候选在虎牙的真实 ACU、观时、拉新、收入或留存，无法验证反挖模型的预测准确性和招募效果。
2. `r_owner` 的业务含义、是否应融合或拆分、是否有跨 owner 的重复开播天数，没有字段字典。
3. `kuaishou_live_mins` 的原始时间单位与统计周期没有字段字典；当前公式只保证复现历史工作簿。
4. 早期 53 人如何从 1,190 人规则总体截取，工作簿未记录。
