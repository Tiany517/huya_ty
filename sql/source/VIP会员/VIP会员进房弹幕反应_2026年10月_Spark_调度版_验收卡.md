## 2. 结果契约

| 项目 | 内容 |
| --- | --- |
| 样本总体 | 仅统计 10 月至少有一位 VIP 用户购卡后进入过的直播场次；再纳入这些场次内的 VIP 购卡后进房和普通用户购卡前进房 |
| 时间口径 | 进房事件 2026-10-01 00:00:00 至 2026-11-01 00:00:00；前窗 `[t-180s,t)`，后窗 `[t,t+179s)` |
| 基础粒度 | 用户进房事件；键为日期、用户、主播、`live_id`、进房时间 |
| 最终粒度 | `user_group + breakdown_type + user_type + acu_bin`；不输出小时 |
| 唯一键 | 上述四个输出维度 |
| 场次键 | `dt + 主播UID + live_id` |
| 用户组 | 10 月首笔成功订单后为 VIP；事件发生时尚未购卡为普通用户 |
| 主指标 | 每个进房事件的房间级前 3 分钟、后 3 分钟有效弹幕数，并扣除触发事件用户本人弹幕 |
| 去除条件 | 主播本人弹幕；`passed<>'0'`；空内容弹幕 |
| 分类口径 | 事件日期、用户、主播、`live_id` 下 `game_label` 唯一为游戏或娱乐；多标签或缺失归入品类未知 |
| ACU 分层 | 沿用原有 `(0,2]` 至 `(100000,+]` 和 `unknown` 分层 |
| 可反驳预期 | 同一用户组内，整体 `event_cnt` 必须等于游戏、娱乐、品类未知三者之和；否则分组或 join 发生放大 |

## 3. 调度模板对齐

| 检查 | 证据 | 状态 |
| --- | --- | --- |
| 使用现成建表结构 | `CREATE TABLE IF NOT EXISTS ... COMMENT ... PARTITIONED BY ... STORED AS ORC` | 通过 |
| 使用动态分区覆盖写入 | CTE 结束后执行 `INSERT OVERWRITE TABLE ... PARTITION (dt)`，最终查询返回常量 `dt='2026-10-31'` | 通过 |
| 启用动态分区 nonstrict 模式 | `SET hive.exec.dynamic.partition.mode=nonstrict`；当前平台默认 strict，完全动态分区会被提前拒绝 | 通过 |
| 输入与目标列数对齐 | 18 个普通字段加 1 个动态分区字段，最终查询共 19 列 | 通过 |
| 不依赖宏变量 | SQL 中不存在 `${...}` | 通过 |
| 不输出小时 | SQL 中不存在 `event_hour` | 通过 |
| 建表字段与最终查询字段对齐 | 18 个普通字段逐一对应，末列 `dt` 对应动态分区字段 | 通过 |
