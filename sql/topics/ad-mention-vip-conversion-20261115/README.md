# 首次提及广告后首次购买平台VIP

2026-11-15已用Presto执行并完成独立复算。源范围2025-01-01至2026-11-14，两表最新可用分区均为2026-11-14。

分母为有效弹幕中至少一次包含“广告”的全期去重发送UID，共584,593人；分子为其中VIP历史首个成功正金额订单发生在其首提广告之后且截止日前的UID，共2,623人，比例0.4486882327%。另269人先买VIP后提广告，不计入分子但保留分母；581,701人未购买。

`main-presto.sql`复用既有弹幕过滤和成功VIP订单口径；`independent-presto.sql`直接count distinct复算分母，并从VIP首单出发验证是否存在更早广告弹幕。两条路径结果精确一致。两份precheck SQL分别核对订单快照和五日弹幕时间字段；`validation-record.md`记录验收。

内容优先trim后askscontent，空时取scontent；passed='0'、lpid非空，保留既有无效luid排除。这里只是提及广告，不使用抱怨分类。VIP最新累计快照status='200'且amount>0，按全历史取首次，不能先截时间窗把续费当首次。

时间代理使用成功订单create_time（创建时间），另用op_time（更新时间）重算仍为2,623，跨广告首提时刻人数0；不声称获取了独立支付到账字段。先提后买是描述关系，不证明广告导致购买；用户观察时长不等，也不是固定7/30天转化。

性能经验：全期UV必须直接按UID并集，不能累加日UV；存在性复算的CTE被多次引用时，Presto可能多次扫描，运行时间高于主查询，应结合平台资源评估。任何一对多展开都必须先回到UID再计算人数。首次提及相同时间与先买VIP均不计入转换。

仓库只保留SQL、汇总数字和验收说明，不含原始弹幕、UID样本、凭据或本机来源映射。
